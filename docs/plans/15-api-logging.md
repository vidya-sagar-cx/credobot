# Plan 15 — FastAPI deployment & JSON-Lines structured logging

A FastAPI app exposing `POST /ask`, `POST /add-document`, `GET /health` and a
`/ws/chat` WebSocket for multi-turn chat that survives client disconnects; every request
(and every WS message) logged as one JSON line with trace ID and timing, with PII masked.

### `credobot/api/logging_mw.py`
```python
class JsonlLogger:
    """Append-only JSON Lines writer at config.LOG_DIR / 'requests.jsonl'.
    threading.Lock; open(..., 'a', encoding='utf-8', newline='\n'); json.dumps(ensure_ascii=False)."""
    def write(self, record: dict) -> None

LOGGER = JsonlLogger()

def log_entry(**fields) -> dict:
    """Builds: {"@timestamp": iso8601 UTC, "level": "INFO", "service": "credobot-api",
    "trace_id", "event": "http_request"|"ws_message"|"ws_disconnect", "method", "path",
    "status_code", "duration_ms", "session_id", "query_masked", "cache_hit",
    "guardrail_events", "intent", "approved", "error"}.
    SAFETY: any string field named query*/text* is passed through mask_pii() here again
    (defence in depth) before writing."""

class RequestLogMiddleware(BaseHTTPMiddleware):
    """For HTTP: trace_id = request.headers.get('x-trace-id') or uuid4().hex;
    store on request.state.trace_id; time with perf_counter; after response set
    'X-Trace-Id' header; write ONE line. Endpoint handlers put masked query/cache_hit/
    events on request.state.log_extra; middleware merges them. Never read the raw body
    in middleware."""
```
WebSocket messages are logged from the handler (middleware doesn't see WS frames): one
line per received message (`event="ws_message"`) and one on disconnect.

### `credobot/api/app.py`
```python
app = FastAPI(title="CredoBot", version="0.1.0")
app.add_middleware(RequestLogMiddleware)

@app.on_event("startup") / lifespan: ensure_index(); warm embedder.

@app.post("/ask", response_model=AskResponse, responses={413: {"model": ErrorResponse}})
def ask(req: AskRequest, request: Request):     # sync def → FastAPI runs it in threadpool
    try: result = pipeline.answer(req.query, req.session_id, trace_id=request.state.trace_id)
    except BudgetExceededError as e: → JSONResponse(413, ErrorResponse(... detail=asdict(e.estimate)))
    request.state.log_extra = {...masked...}
    return AskResponse(...)

@app.post("/add-document", response_model=AddDocumentResponse) → index.add_document(...)
@app.get("/health", response_model=HealthResponse)

@app.websocket("/ws/chat")
async def ws_chat(ws: WebSocket, session_id: str | None = None):
    await ws.accept(); session_id = session_id or uuid4().hex[:12]; turn = 0
    try:
        while True:
            raw = await ws.receive_text()
            trace_id = uuid4().hex; t0 = perf_counter(); turn += 1
            try:
                msg = WSIn.model_validate_json(raw)   # also accept plain text
                result = await run_in_threadpool(pipeline.answer, msg.query, session_id, trace_id)
                out = WSOut(...)
            except BudgetExceededError / ValidationError as e: out = WSOut(error=...)
            LOGGER.write(log_entry(event="ws_message", ...))
            await ws.send_text(out.model_dump_json())
    except WebSocketDisconnect as e:
        LOGGER.write(log_entry(event="ws_disconnect", session_id=..., code=e.code))
        return     # server keeps running; session memory kept for reconnect
```
Do not let any other exception escape the WS loop silently: catch `Exception`, log it
with `level="ERROR"`, try to send an error frame, then close with code 1011.

## Pitfalls
- `BaseHTTPMiddleware` doesn't see WebSocket traffic — log WS from the handler.
- Pipeline is sync & CPU-bound — use `def` endpoints / `run_in_threadpool` so the event
  loop (and other WS clients) aren't blocked.
- Windows: log file opened in append mode with `newline="\n"` to keep JSONL LF-only.
- TestClient WS disconnect: closing the client raises `WebSocketDisconnect` server-side
  on next `receive_text` — that's the path under test.
