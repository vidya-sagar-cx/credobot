# AGENTS.md — instructions for AI agents (and humans) working in this repo

CredoBot is a Finance-track (Banking & FinTech) loan-support agent: RAG over a policy
knowledge base, a CrewAI crew, an Autogen review stage, guardrails, governance and a
FastAPI backend. Everything must run under `MOCK_LLM=true` with **zero API keys and zero
network access** (after the one-time embedding-model download).

Environment setup: see [`docs/SETUP.md`](docs/SETUP.md).

## How work is organised
All implementation work is split into small plan docs in [`docs/plans/`](docs/plans/).
One plan = one unit of work = one commit. Status lives in
[`docs/plans/PROGRESS.md`](docs/plans/PROGRESS.md); values that later plans depend on
(seed, thresholds, chosen collection, versions…) live in
[`docs/plans/DECISIONS.md`](docs/plans/DECISIONS.md).

## Protocol — follow exactly
1. `git switch feat/loan-support-agent && git pull` (if a remote exists).
   Read `docs/plans/PROGRESS.md` and `docs/plans/DECISIONS.md`.
2. **Pick a plan.** If any row is `in-progress`, resume that one first (the ticked
   `- [x]` boxes in its doc show where the previous agent stopped). Otherwise take the
   lowest-numbered `todo` row whose `Deps` are all `done`.
3. **Claim it.** Set its row to `in-progress`, fill `Owner` (agent/person) and `Updated`
   (YYYY-MM-DD). Commit nothing yet.
4. **Implement.** Work through the doc's `Steps` in order. Tick each checkbox
   (`- [ ]` → `- [x]`) in the plan doc as soon as that step is done. If you must stop
   mid-plan, commit with message `plan NN: wip <what was done>` so the next agent resumes
   from the ticked boxes.
5. **Verify.** Run every command in the doc's `Verify` section. All must pass. If one
   cannot pass, set the row to `blocked`, explain why in `Notes`, commit
   `plan NN: blocked <reason>`, and stop.
6. **Record.** Write every key listed under `Record in DECISIONS.md` (tag with the plan
   ID). Never change a value another plan recorded without updating every plan that read it.
7. **Finish.** Set the row to `done`, update `Updated`, then make ONE commit with the
   message given in the doc. The commit contains code, tests, transcripts and the
   tracking-file edits together. Do not push unless the user asks.

## Ground rules
- Only touch files the plan lists (plus `PROGRESS.md`, `DECISIONS.md`, the plan doc).
  If you need to change something outside scope, note it in `Notes` and in the plan doc.
- Don't write ahead into a later plan's scope, even if it looks easy.
- Run everything through uv: `uv run python …`, `uv run pytest …`. Never `pip install`.
  Add dependencies with `uv add <pkg>` (dev: `uv add --dev <pkg>`) and commit `uv.lock`.
- **Cross-platform (Windows contributors):** Python entry points only (no shell scripts,
  no Makefile); `pathlib.Path` for paths; every `open()`/`read_text()`/`write_text()`
  passes `encoding="utf-8"`; no hard-coded `/tmp`; use `tempfile`/pytest `tmp_path`.
- **Network:** `credobot/config.py` must be imported before crewai/chromadb anywhere;
  it sets `CREWAI_DISABLE_TELEMETRY=true`, `OTEL_SDK_DISABLED=true`,
  `ANONYMIZED_TELEMETRY=False`, `MOCK_LLM=true` defaults.
- Tests must pass with `MOCK_LLM=true` and no API keys: `uv run pytest -q`.
- Transcripts go in `transcripts/*.md`, generated by code (never hand-edited).
- Only fabricated data. Never real names, PAN, Aadhaar or account numbers.
- Commit message trailer: `Co-Authored-By: <agent name> <email>` if your tooling requires it.
